# HAKOOT_

**Like Kahoot, but to actually learn something.**

Hakoot is a real-time interactive learning platform where hosts create games with theory steps, annotated code blocks, and live quizzes — then guide participants through them in a live session.

## Features

- **Theory Steps** — Rich Markdown content with syntax-highlighted code blocks and clickable line annotations.
- **Live Quizzes** — Timed multiple-choice questions with instant scoring and a real-time leaderboard.
- **Real-Time Sessions** — Host a session, share an invite code, and all devices sync instantly.
- **Internationalization** — Full i18n support (English and Italian) via next-intl.
- **Email Invites** — Send session invitations directly from the app via Resend.
- **Google & Password Auth** — Hosts sign in with Google or email/password through Convex Auth.

## Getting Started

### 1. Clone and install

```bash
git clone https://github.com/Repressoh/hakoot.git
cd hakoot
bun install
```

### 2. Set up Convex

Create a new Convex project and link it:

```bash
bunx convex init
```

This will create a `.env.local` file with your `CONVEX_DEPLOYMENT` and `NEXT_PUBLIC_CONVEX_URL`.

Push the database schema and functions to Convex:

```bash
bunx convex dev --once
```

### 3. Configure environment variables

Add the following to your `.env.local`:

```dotenv
# Convex (auto-generated by `convex init`)
CONVEX_DEPLOYMENT=dev:your-project-name
NEXT_PUBLIC_CONVEX_URL=https://your-project.convex.cloud

# App
NEXT_PUBLIC_APP_URL=http://localhost:3000

# Resend (optional — needed for email invites)
RESEND_API_KEY=re_your_api_key
RESEND_FROM_EMAIL=noreply@yourdomain.com

# HMAC secret for invite link signatures (generate with: openssl rand -hex 32)
INVITE_HMAC_SECRET=your_random_hex_string

# Google OAuth (optional — needed for Google sign-in)
AUTH_GOOGLE_ID=your_google_client_id
AUTH_GOOGLE_SECRET=your_google_client_secret

# JWT key for Convex Auth (generate with: openssl genpkey -algorithm ed25519 | openssl pkey -outform DER | tail -c 32 | base64)
JWT_PRIVATE_KEY=your_base64_key
```

Set the corresponding environment variables in the Convex dashboard:

| Convex Dashboard Variable | Value |
| --- | --- |
| `CONVEX_SITE_URL` | Your Convex site URL (e.g. `https://your-project.convex.site`) |
| `JWKS` | Your JWKS public key |
| `AUTH_GOOGLE_ID` | Same as above |
| `AUTH_GOOGLE_SECRET` | Same as above |
| `RESEND_API_KEY` | Same as above |
| `RESEND_FROM_EMAIL` | Same as above |
| `INVITE_HMAC_SECRET` | Same as above |

Refer to the [Convex Auth docs](https://labs.convex.dev/auth) for full setup instructions.

### 4. Run the development server

```bash
bun run dev
```

This runs `convex dev --once` (to sync types) then starts Next.js at [http://localhost:3000](http://localhost:3000).

In a separate terminal, start the Convex dev server for live function reloading:

```bash
bun run dev:convex
```

## Docker Deployment

The project includes a production-ready Docker setup using multi-stage builds with hardened, distroless images (~73 MB final size).

### Quick start with Docker Compose

**1. Create a `.env` file** in the project root with at least:

```dotenv
NEXT_PUBLIC_CONVEX_URL=https://your-project.convex.cloud
NEXT_PUBLIC_APP_URL=https://your-domain.com
CONVEX_DEPLOY_KEY=prod:your-deploy-key
```

Get your deploy key from the [Convex dashboard](https://dashboard.convex.dev) → Settings → Deploy keys.

**2. Deploy Convex functions** (one-time, or after schema/function changes):

```bash
docker compose --profile setup run --rm deploy-convex
```

**3. Build and run the app:**

```bash
docker compose build
docker compose up -d
```

The app will be available at `http://localhost:3000`.

### Standalone Docker build

```bash
docker build \
  --build-arg NEXT_PUBLIC_CONVEX_URL=https://your-project.convex.cloud \
  --build-arg NEXT_PUBLIC_APP_URL=https://your-domain.com \
  -t hakoot .

docker run -p 3000:3000 hakoot
```

> **Note:** `NEXT_PUBLIC_*` variables are inlined into the JavaScript bundle at build time by Next.js. They must be passed as build args — setting them as runtime container env vars has no effect on the client.

### Docker image details

| Property       | Value                                   |
| -------------- | --------------------------------------- |
| Build image    | `oven/bun:1.3.10-alpine` (pinned by digest) |
| Runtime image  | `oven/bun:1.3.10-distroless` (pinned by digest) |
| Final size     | ~73 MB                                  |
| Runs as        | Non-root (uid 1000)                     |
| Filesystem     | Read-only                               |
| Capabilities   | All dropped                             |

```
lib/                    # Shared utilities
```

## Security scanning (deepsec)

This repo includes a [deepsec](https://github.com/vercel-labs/deepsec) workspace
at `.deepsec/` for agent-assisted vulnerability scanning.

```bash
cd .deepsec && bun install          # once
bun run deepsec:scan                # free regex scan
bun run deepsec:status              # scan progress
bun run deepsec:process             # Codex + evomap-gpt-5.5 (needs .deepsec/.env.local)
bun run deepsec:revalidate          # optional false-positive reduction
bun run deepsec:export              # export findings
```

Copy `.deepsec/.env.example` to `.deepsec/.env.local` and set
`OPENAI_API_KEY` + `OPENAI_BASE_URL` for your OpenAI-compatible provider.
See `.deepsec/README.md` for details.
